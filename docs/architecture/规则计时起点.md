# 规则计时起点

Android 的 UsageEvents 属于系统，卸载止间不删除其他应用的使用记录。首页及每日归档继续展示系统保留的实际历史；规则判定另外使用本次安装内保存的统计起点，不能把安装或首次启用前的历史当作新规则用量。

## 生效与恢复

每个策略第一次以已开启且含有规则的状态保存时建立 `UsageTrackingStart`。默认关闭的规则组没有起点。起点与配置在同一 Room 事务内写入已有 `storage_meta` 表，事务成功后才随 `PolicySnapshot` 发布；失败不发布候选起点。

规则统计使用自然周期与起点的交集：全天限时和限次仍按每日恢复时间恢复，时段限时和限次仍按各自时段恢复，频率限次仍按滚动窗口释放次数。连续提醒从固定起点建立首个周期；足额连续休息后按原逻辑清零。启用时应用已在前台，时间从生效边界裁剪，不伪造一次新的打开。

| 操作 | 起点及累计量 |
| --- | --- |
| 默认关闭的组首次开启 | 在成功保存的生效边界建立新起点 |
| 无为、修心、闭关相互切换 | 保留起点和原累计量；切换前结算旧强度，后续增量沿用同一周期 |
| 规则参数或修订号变化 | 不重新建立首次起点，不赠送新的额度 |
| 服务重连、进程重启、覆盖安装 | 恢复原起点及已保存周期，不重复累计历史 |
| 删除策略后重新创建 | 为新策略重新建立起点 |
| 卸载重装或数据库从另一安装恢复 | 建立本次安装的新统计身份，旧周期不参与新统计 |

同次开机，起点按保存的单调时间投影到当前查询墙钟，并保留已保存墙钟起点作为下界；墙钟回拨到起点之前时，本次规则查询区间为空，避免重新纳入旧历史。跨开机保留墙钟起点，连续周期的跨开机保留与休息验证仍使用原实现。系统事件只有墙钟时间，本次未重建手动改时前后的完整时间轴。即时的时段禁用不依赖累计用量，继续按已保存日程生效；明确的零额度不获得额外宽限。

## 安装与周期身份

`InstallationIdentityStore` 在 `getNoBackupFilesDir()/usage_installation_id` 中原子保存安装 UUID。该文件不参与系统备份，覆盖安装保留，卸载重装后重新生成。`UsageTrackingStore` 将对应安装身份和策略起点保存在已有元数据表中；恢复的元数据属于另一安装时，初始化先同步清空旧展示、休息及禁用事实，再在同一 Room 事务中删除应用与连续周期的恢复检查点、撤销旧临时放行并保存新起点。其他检查点与历史审计保留。

偏好清理必须在新安装身份提交前完成。清理失败时初始化失败；偏好已清理而数据库事务失败时，旧安装身份及数据库记录一起回滚，下次初始化重复清理后再提交。只有事务完成才发布快照。同次安装重启不执行这项清理。跨安装隔离以安装 UUID 为依据，设备启动标识碰撞或来源设备墙钟较快都不能使旧事实重新生效。

连续周期的 `continuous_usage_cycles` 记录增加 `tracking` 字段。读取必须匹配当前策略的统计身份，防止备份恢复的旧累计覆盖新起点。原安装的休息事实和恢复检查点也不能重建新安装的周期。全天与时段提醒共用该边界，首次启用之前已经结束的时段不补生成提醒。

主入口是 `ZhijianStorage` 的初始化与配置事务、`UsageEvidenceReader` 的规则证据聚合，以及 `ContinuousUsageReader` / `ReminderUsageReader` 的周期读取。没有增加 Room 表、列或数据库版本，现有 schema 不变。

## 验证范围

`UsageTrackingStartTest` 声明固定起点、墙钟投影、重启及旧事实过滤回归。`UsageEvidenceReaderTest` 从包含旧使用记录的合成时间轴调用实际证据聚合及规则引擎，覆盖全天、时段、三类限次、全局亮屏额度、三档强度及启用时已经在前台的场景。`UsageTrackingStoreTest` 使用独立 Room 数据库覆盖首次开启、强度修改、重新打开数据库、另一安装及事务回滚。`RetreatStorageTest` 另验证连续周期只接受匹配的统计身份，忽略另一安装的记录不会删除它。`InstallationRestoreTest` 通过正式存储初始化入口覆盖启动标识碰撞、来源墙钟较快、同次安装重启保留进度，以及偏好清理后数据库提交失败的回滚与重试；数据库、偏好和安装身份文件均使用独立测试空间。

本次只做静态核对，未编译、安装、运行测试或进行设备复现。真实卸载重装、授权顺序、备份恢复和强度切换仍需要设备验证。这次修复聚焦安装与首次启用起点；关闭期间的分段统计、成员变更的历史归属、单词展示起点和放行保存排队等独立审查项没有在本次变更中调整。
