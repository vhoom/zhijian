# 项目结构

zhijian（止间）是使用 Java 与 XML View 的 Android 使用管理应用。目录、命名与源码文件数量按当前工作区核对，依赖分析基线与统计范围见[索引](README.md)。

## 工程边界与目录

[settings.gradle](../../settings.gradle) 将工程名设为 `zhijian`，只声明 `include ':app'`。[app/build.gradle](../../app/build.gradle) 应用 Android application 插件，使用 Java 17，`minSdk 29`、`compileSdk 36`、`targetSdk 36`。逻辑包不是独立 Gradle 模块。

应用显示名称由 `brand.xml` 的 `app_name` 配置为“止间”，Java 命名空间与应用 ID 为 `github.vhoom.zhijian`。应用专属入口和主题使用 `Zhijian` 前缀；`InterceptionFlow`、`ModeFlowPlan` 中的 Flow 表示交互流程。


## 顶层职责

以下路径相对于 `app/src/main/java/github/vhoom/zhijian/`，文件数包含子包。

| 区域 | 文件数 | 主要职责与阅读入口 |
|---|---:|---|
| 根包 | 1 | [ZhijianApplication](../../app/src/main/java/github/vhoom/zhijian/ZhijianApplication.java)：安装诊断、启动存储、注册安装包观察、调度归档并检查必需资源 |
| `accessibility` | 3 | [ZhijianAccessibilityService](../../app/src/main/java/github/vhoom/zhijian/accessibility/ZhijianAccessibilityService.java)：窗口事件、评估调度、过期结果过滤与拦截启动；同包另有包过滤器、连接状态入口 |
| `runtime` | 4 | [InterceptionRuntime](../../app/src/main/java/github/vhoom/zhijian/runtime/interception/InterceptionRuntime.java)：组装规则、用量证据、会话及通行证；另外负责安装变化和归档协调 |
| `domain` | 35 | [RuleEngine](../../app/src/main/java/github/vhoom/zhijian/domain/interception/RuleEngine.java)、[InterceptionFlow](../../app/src/main/java/github/vhoom/zhijian/domain/interception/InterceptionFlow.java)、[UsageTimeline](../../app/src/main/java/github/vhoom/zhijian/domain/usage/UsageTimeline.java)：规则计算、交互状态转换与时间轴计算 |
| `data` | 104 | [ZhijianStorage](../../app/src/main/java/github/vhoom/zhijian/data/store/ZhijianStorage.java)：存储装配与提交快照；其他子包承载模型、系统适配、DAO、偏好和文件存储 |
| `ui` | 82 | [MainActivity](../../app/src/main/java/github/vhoom/zhijian/ui/activity/MainActivity.java)、[InterceptionActivity](../../app/src/main/java/github/vhoom/zhijian/ui/interception/InterceptionActivity.java)：主界面和拦截交互；通过绑定器与控件包拆分展示职责 |
| `util` | 21 | [TaskQueue](../../app/src/main/java/github/vhoom/zhijian/util/concurrent/TaskQueue.java)、[PermissionStatusReader](../../app/src/main/java/github/vhoom/zhijian/util/permission/PermissionStatusReader.java)、[DiagnosticLog](../../app/src/main/java/github/vhoom/zhijian/util/diagnostics/DiagnosticLog.java)：并发、系统权限、诊断及格式支持 |

`domain` 没有因此自动获得独立编译能力；`data` 也不全是数据库代码。实际跨包关系见[模块依赖](模块依赖.md)。

## data 的内部划分

| 子包 | 文件数 | 存放内容 |
|---|---:|---|
| `model` 及子包 | 41 | 应用、策略、逐日参数、运行会话、通行证、交互设置和用量模型；`RuleGroup` 同时用于配置草稿与有效策略 |
| `source` | 12 | Android 用量事件、已安装应用、桌面应用、连续使用证据及静心保护读取；`CachedAppCatalog` 组合扫描源与缓存接口 |
| `db` 及子包 | 20 | 1 个 Room 数据库、5 个 DAO、14 个实体 |
| `store` 及子包 | 30 | 存储门面、编解码、快照、应用缓存、设置、会话、连续周期与词库存储 |
| `export` | 1 | 诊断报告导出 |

[ZhijianDatabase](../../app/src/main/java/github/vhoom/zhijian/data/db/ZhijianDatabase.java) 的数据库文件是 `zhijian.db`，当前 schema 版本为 1，启用 WAL。对应导出为 [1.json](../../app/schemas/github.vhoom.zhijian.data.db.ZhijianDatabase/1.json)。

schema 目录按数据库类的完整名称生成，保存表、字段及索引定义，供结构审查与维护，不含手机用户数据。类和目录更名没有改变这 14 张表的结构。当前开发版本不迁移旧文件名的数据库；覆盖安装时会使用新的 `zhijian.db`，原数据库内容不会自动带入。使用历史 JSONL 导出的格式标识为 `zhijian.usage`，格式版本仍为 2。

持久化并非全部进入 Room：

| 状态 | 当前入口与载体 |
|---|---|
| 规则、规则成员、通行证、审计记录、检查点、用量历史及归档、数据库词库 | `ZhijianStorage` 与各业务 Store，经 Room DAO 读写 |
| 待展示会话、待休息记录、限制记录 | [PendingInterceptionStore](../../app/src/main/java/github/vhoom/zhijian/data/store/interception/PendingInterceptionStore.java)，`pending_interceptions` 私有偏好 |
| 当前访问已确认的禁用规则 | [BlockContinuationStore](../../app/src/main/java/github/vhoom/zhijian/data/store/interception/BlockContinuationStore.java)，`block_continuations` 私有偏好 |
| 连续使用周期 | [ContinuousUsageStore](../../app/src/main/java/github/vhoom/zhijian/data/store/usage/ContinuousUsageStore.java)，`continuous_usage_cycles` 私有偏好 |
| 页面、主题、交互开关等设置 | [GlobalSettings](../../app/src/main/java/github/vhoom/zhijian/data/store/settings/GlobalSettings.java)、[InteractionSettingsStore](../../app/src/main/java/github/vhoom/zhijian/data/store/settings/InteractionSettingsStore.java)；强度和总额度通过 `ZhijianStorage` 写配置，不能因类名而全部归为偏好 |
| 应用清单缓存 | [AppCatalogCache](../../app/src/main/java/github/vhoom/zhijian/data/store/apps/AppCatalogCache.java) 接口与 [AppCatalogFileStore](../../app/src/main/java/github/vhoom/zhijian/data/store/apps/AppCatalogFileStore.java) 实现 |

## UI 与规则计算的阅读顺序

| 需求路径 | 建议阅读的源码入口 |
|---|---|
| 首页用量与应用清单 | `MainActivity` → `DashboardBinder`、`UsageStatsReader`、`UsageArchiveStore`、`CachedAppCatalog` |
| 编辑单应用或规则组 | `AppPolicyActivity` / `RuleGroupEditActivity` → `ui.component.rule` → `AppPolicyStore` / `RuleGroupStore` → `ZhijianStorage` |
| 全局设置与引导 | `SettingsActivity` → `ui.settings`、`SetupGuideBinder` → 对应设置 Store、权限工具 |
| 判断是否拦截 | `ZhijianAccessibilityService` → `InterceptionRuntime` → `UsageEvidenceReader` / `ReminderUsageReader` → `RuleEngine` |
| 拦截页动作与挑战 | `InterceptionActivity` → `InterceptionFlow` / `ModeFlowPlan` → `InterceptionPageRegistry` → 页面实现 |
| 页面完成后的保存 | `InterceptionOutcomeWriter` → `RuntimeStateStore` → 会话确认或清理 |

`ui.interception` 进一步分为 `request`（Intent）、`session`（会话与结果写入）、`page`（页面）、`page.support`（动作及呈现支持）、`copy`（文案）、`preview`（预览）。普通界面使用 `ui.binder`、`ui.settings` 和 `ui.component` 复用逻辑。

`domain.interception` 下的 `count`、`hold`、`word`、`sudoku`、`copy` 分别承载次数评估、按压进度、单词挑战、数独棋盘与进度和文案轮换；`domain.usage` 承载时间轴、连续周期、休息、日期与用量展示预算等计算。

## 系统入口与资源

[正式 Manifest](../../app/src/main/AndroidManifest.xml) 声明 `ZhijianApplication`、启动页 `MainActivity`、内部编辑/设置/诊断/预览页面、`singleTask` 的 `InterceptionActivity`、无障碍服务以及 `UsageArchiveJobService`。

- [无障碍服务 XML](../../app/src/main/res/xml/zhijian_accessibility_service.xml) 订阅窗口状态变化，`canRetrieveWindowContent=false`；前台观察和系统 UsageEvents 共同提供证据。
- 系统按组件名保存无障碍授权；已有安装更新为 `ZhijianAccessibilityService` 后，需要在系统设置重新开启该服务。
- [Debug Manifest](../../app/src/debug/AndroidManifest.xml) 增加专用调试 Activity。预览辅助类也存在于 `main`，不能仅以目录判断是否为 Debug 功能。
- `res/layout` 放页面与控件布局，`values` / `values-night` 放主题等资源，`res/xml` 放服务及备份配置；UI 复用约定见 [UI 设计规范](../UI设计规范.md)。
- `assets/word_catalog.tsv` 与 `assets/English/*.csv` 提供词库，`assets/about/*.txt` 提供关于页面正文。
