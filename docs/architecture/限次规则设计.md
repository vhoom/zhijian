# 限次规则设计

单应用和规则组使用同一套八卡编辑器。全天频率限次只有一条窗口与次数配置；时段限次可保存多个不重叠的独立时段。启用额度统一为 1–99 整数，零只表示未填写或关闭的参数。次数输入框没有范围提示，输入监听只更新草稿并清除旧错误；保存时先检查原始文本，再由 `RuleGroupValidator` 检查完整候选。错误统一显示“无效，请修改”或“数值过大”，保留原文并通过简洁原生弹窗返回修改位置。三种限次都允许前 N 次真实打开，第 N+1 次触发当前强度的限制。

## 统计范围与恢复

| 类型 | 统计范围 | 自然恢复 |
| --- | --- | --- |
| 全天限次 | 用户每日恢复点至本次检查时刻 | 下一次每日恢复点 |
| 时段限次 | 当前独立时段开始至本次检查时刻 | 该时段结束；跨午夜保留开始星期 |
| 全天频率限次 | (当前时刻减窗口长度，当前时刻] | 足够多的旧打开记录到期，使次数回到允许范围 |

打开时刻按整数毫秒保存，滚动起点使用窗口下界加一毫秒，到期记录立即移出。反复离开后重新打开也进入滚动记录；超过额度多次时，不能只等待最老的一条过期。午夜和每日恢复点不清空频率窗口内的近期记录，切换星期后用新星期的窗口及次数重新判定。

`UsageTimeline` 统一识别真实访问：同应用 Activity 交接及实际拦截页返回不重复计数，桌面、其他应用或锁屏后返回重新计数。同组应用的真实打开按 `PolicySnapshot` 实际生效归属汇总，独立配置或其他更靠前规则组接管的应用不消耗本组额度。

## 模块边界

`CountRuleEvaluator` 的范围策略工厂集中登记全天、时段和滚动统计策略。策略只生成查询范围和恢复边界，不读取 Android 服务或修改策略。`UsageEvidenceReader` 执行这些查询，`UsageTimeline.openingSnapshot` 输出独立只读的 `OpenCountSnapshot`；`UsageEvidence` 的连续提醒副本操作保留同次限次快照。

`RuleEngine` 合并限次与其他禁用。多条禁用同时命中时，决定保留原因优先级和最晚自然解除时间，下一次检查仍采用较早的额度释放或时段边界。运行层恢复持久化会话时保留这条复查要求，拦截页按单调时间期限调度；挑战步骤重绘不顺延期限，异步查询耗时计入期限。系统证据不可用时不猜测打开次数，但活动时段的复查边界仍保留。

新增统计范围时在策略工厂登记对应规则类型，补齐编辑参数、范围校验和稳定存储键；查询读取器与引擎继续使用同一批策略结果，避免分别维护规则解释。

`RuleInputLimits` 为次数、时长、休息、放行和手动名称提供不可变约束，固定上界与当前时段长度在同一工厂组合。`RuleInputBinding` 适配原始输入、必填状态及约束读取器，独立于模型的零值，能识别空输入、小数次数和解析溢出。编辑页只在保存与确认应用时调用校验；`RuleValidationFeedback` 负责通用提示、可见位置和键盘恢复，不拼接真实范围。所有手动输入的保存约束见[配置说明](../界面与配置说明.md#手动输入校验)。

## 星期草稿与存储

`RuleDayParameterAdapter`、`RuleDayParameters.copy`、`RuleGroup.copy` 和 `RuleDraftState` 一起保留频率窗口、频率次数及每段次数。`WeekdayRuleDraft` 只在后台事务成功后更新保存标记和复制来源；候选失败、取消或页面重建不改写其他星期。运行窗口身份加入开始星期，跨午夜保留原日次数和放行时长。

原始文本按规则类型、时段ID与参数角色单独保存，系统恢复不会触发用户编辑；同一时段的增删重绘保留仍存在输入，时间选择器不清除绑定。`RuleGroupValidator.Result` 保留星期、窗口、数值/次数/休息/放行角色及过大分类；关闭卡片、缺失窗口或其他星期的错误通过可见卡片或星期入口回退定位，不改写当前草稿，也不标记当前日的无关参数。新时长上界属于保存配置校验，当前格式读取继续使用非负值、精度和身份的结构校验，使原值可进入编辑器修正；数据库与JSON格式保持当前版本。

| 参数 | 当前 Room 字段 | 星期 JSON 字段 |
| --- | --- | --- |
| 全天次数 | `policy_rule.limitCount`，类型 `daily_count` | `count` |
| 频率窗口与次数 | `policy_rule.durationMs` / `limitCount`，类型 `rolling_count` | `frequencyWindow` / `frequencyCount` |
| 时段次数 | `policy_window.limitCount`，`INTEGER NOT NULL DEFAULT 0`，类型 `window_count` | 每个窗口的 `count` |

时段次数与时长分别保存，限次窗口的 `durationMs` 为零。当前开发数据库基线为 1，当前 schema 同步次数字段、默认值和 Room 身份哈希；七日 JSON 格式为版本 3，不转换旧格式。JSON 次数只接受范围内的整数数值，拒绝小数、字符串、超大整数和缺失字段，避免 `getInt` 截断为其他额度。关闭条件可保留零值，启用条件保存前再检查 1–99。

## 验证范围

本地回归声明覆盖三档 N/N+1、独立时段、精确滚动到期、反复打开、组合禁用、会话复查、真实打开快照和星期复制/取消，并补齐输入格式、数值上界、严格端点及错误角色。设备回归声明覆盖两入口八张卡、单条频率、编辑与保存校验分离、原文与Bundle恢复、通用弹窗、时段重绘、错误定位和生命周期，以及严格JSON和数据库关闭重开。当前仅完成静态核对，未运行测试、编译、Lint 或设备视觉验证；执行入口见[测试目录](../testing/README.md)。
