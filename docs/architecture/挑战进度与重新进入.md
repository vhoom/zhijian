# 挑战进度与重新进入

正式单词和数独挑战各保留一局全局进度。未开始时退出再进重新出题；开始后跨应用、退出和页面重建继续原局，完成后结束本次拦截才换下一局。主句仍按原规则会话保持，挑战进入标识不改变休息计时或放行判定。

## 开始与进入边界

| 情况 | 处理 |
| --- | --- |
| 单词还未选择答案，或只在停留锁定期间点击 | 未开始，重新进入刷新 |
| 单词有效选择过任一答案，包括答错 | 保留本局词库、题量、题号和当前题解锁时刻 |
| 数独只选中过格子，没有成功填写 | 未开始，重新进入刷新 |
| 数独成功填写过，之后又清空 | 已开始，保留原题及清空后的填写状态 |
| 旋转屏幕、主题导致的页面重建、后台规则复查 | 原次进入，未开始的题也不刷新 |
| 完整离开前台后返回，或收到实际重新打开请求 | 新次进入，存储自行判断刷新或恢复 |

`InterceptionActivity` 创建独立的 `challengeEntryId`，通过只读 `PageSession` 传给页面。它与运行会话身份、主句和首屏控件种子分离。配置重建保存此标识；实际离开时标记刷新，Android 10+ 的停止后状态保存不再保留旧标识，因此后台进程恢复也按重新进入处理。`onNewIntent` 的重新打开请求更换标识，内部规则更新继续保留。

## 持久化与依赖

| 入口 | 职责 |
| --- | --- |
| `ui/interception/page/WordPage`、`SudokuPage` | 接收输入，等待保存，发布已提交界面与完成事件 |
| `data/store/interception/WordProgressStore`、`SudokuProgressStore` | 每类独立后台串行队列、AtomicFile 写入、显式同步及回读、版本校验 |
| `domain/interception/word/WordProgress`、`sudoku/SudokuProgress` | 开始边界、完成身份、进入恢复策略和不可变进度 |
| `domain/interception/word/WordQuizSession`、`sudoku/SudokuBoard` | 原有答题与棋盘规则 |

路径相对 `app/src/main/java/github/vhoom/zhijian/`。页面向存储提交操作，存储依赖领域对象和只读词库，领域对象不引用页面或存储。未新增 Room 表。

单词文件为 `files/word_progress.json`，字段包含 `attempt`、`entry_id`、`revision`、`count`、`dwell_ms`、`catalog`、`question_index`、`unlock_at_elapsed_ms`、`boot_id`、`started`、`completed_session`。固定本局种子与内置词库配置后，按原出题算法重现题目和选项。设备重新启动时保留题号，为当前未完成题重新建立完整停留期限；同一启动下恢复原解锁时刻。已答局不因用户修改词库、题量或停留配置而清空。

数独文件及题面编码见[数独挑战与进度](数独挑战与进度.md)。所有止间页面固定竖屏。结果保存中由原生生命周期保留不持有页面的 `InterceptionSubmission`，新实例观察原后台任务；系统状态另外保存稳定提交身份、已确认出口和双时钟，进程恢复以相同参数幂等重放。保存期间显示保存页，不重新加载已完成挑战；后台完成时保留返回意图，到页面重新进入前台后执行。

两类文件各自保存；存储按本局身份和版本拒绝旧页面回写。错误答案也必须保存成功后才标记为已开始。完成事件在最后一步保存成功后才发送，普通退出或继续的结果成功保存后标记完成局已结束；仅改名称或等价保存规则时保留会话版本，不结束已完成挑战。

加载或保存失败保留原文件，页面显示系统提示与重试入口；暂停不取消已排队的保存，后台回调不导航。Debug 预览保留固定种子与 Bundle，始终隔离正式文件。

## 验证范围

`WordProgressTest` 覆盖未答进入边界、答错后恢复、重启时钟和完成退出；`WordProgressStoreTest` 使用独立文件覆盖重进换题、同次重建、锁定点击、已答配置保留、题号恢复、过期写入拒绝及损坏保留。数独领域与存储用例补充未填写刷新、填写再清空保留。正式继续用例等待每次单词答案落盘，设备会话备份并恢复用户单词文件。

本次仅核对源码、资源和文档，未运行测试、编译或真机操作。实际后台返回、旋转、主题重建、保存中退出及重启恢复仍需设备验收；不能将此前真机结果作为这些变更的通过证据。
