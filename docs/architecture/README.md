## 当前架构结论

- 构建上只有一个 Android 模块 `:app`。`ui`、`domain`、`runtime`、`accessibility`、`data`、`util` 是 Java 包组织的逻辑边界，没有各自独立的 Gradle 编译边界。
- 规则计算与页面交互已经分别集中到 `RuleEngine` 和 `InterceptionFlow`。Android 事件读取、运行协调、页面呈现与存储也有对应入口。
- 包依赖并非严格单向：`data` 与 `domain` 相互引用，`util.permission` 引用无障碍服务，部分模型直接使用数据源或领域类型。不能把目录树直接视为无环分层图。
- 一致性主要依靠已提交快照、串行写入、周期锁以及会话和版本检查。Room、SharedPreferences、页面状态各有边界，不能视为同一个事务。

上述结论分别来自 [settings.gradle](../../settings.gradle)、[RuleEngine](../../app/src/main/java/github/vhoom/zhijian/domain/interception/RuleEngine.java)、[InterceptionFlow](../../app/src/main/java/github/vhoom/zhijian/domain/interception/InterceptionFlow.java)、[ZhijianStorage](../../app/src/main/java/github/vhoom/zhijian/data/store/ZhijianStorage.java) 及依赖文档列出的具体引用。

## 分析口径

| 范围 | 本次处理方式 |
|---|---|
| 正式 Java 源码 | 依赖矩阵按基线的 239 个 `.java` 文件读取包声明与显式 import；当前文件数量见[项目结构](项目结构.md) |
| 关键调用链 | 阅读启动、无障碍调度、规则判定、连续用量、快照、页面流程及结果写入的方法体 |
| 工程与系统入口 | 核对 Gradle 配置、版本目录、正式与 debug Manifest、无障碍服务 XML |
| 资源与存储 | 核对资源目录、assets、Room 实体与当前 schema 路径 |
| 测试目录 | 统计源码文件并提供回归入口；实际执行范围见[真机验证](../testing/真机验证.md) |
| 历史说明 | 作为导航和背景，不把旧文档中的测试通过记录算作本次验证 |

依赖矩阵统计的是显式 import 声明数，排除 Android/JDK/第三方类型及生成的 `R`、`BuildConfig`。同包引用、方法体中的全限定类型、XML 引用和实际运行次数不在矩阵内；关键全限定引用已通过方法体补充说明。这是源码静态盘点，不是完整 AST、字节码或运行时调用图。

包之间双向引用称为“包级依赖环”。它不直接证明两个对象互相持有，也不直接证明存在死锁。热点引用数表示修改的潜在影响范围，不是质量评分。
