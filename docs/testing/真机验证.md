## 本次修复与验证边界

- 前台允许结果按额度和本轮计算所在日期的午夜中较早的边界安排复查，并扣除后台计算及主线程排队耗时。5 个本地时间边界用例、4 个真机 Handler 用例通过。
- 以正式 `RuleEngine` 测试替换未接入运行链路的旧优先级辅助类测试；设备夹具分别保存展示、休息、限制与周期。
- 分组服务测试满足当前至少两个成员的约束；第二成员仅是逻辑测试身份。两个真实应用之间的累计与切换由分组用量测试覆盖。
- 按压手势在页面切换后仍向原 View 发送抬起事件；单词挑战按正式候选选择策略准备会话种子，并断言正式页面复用该会话。没有使用预览请求或直接写入放行结果。
- 恢复步骤逐项执行并汇总错误，保存组之前登记清理。测试后比对发现测试应用独立周期遗漏，已补齐清理并复测。

时间边界用例注入固定时间并检查实际 Handler 排队，没有修改手机时钟或时区，也没有实际等待跨午夜。`ForegroundEvaluationTest` 的服务实例方法断言不等同于系统连接；真实服务、前台窗口及正式页面由表中的集成用例验证。本次分批结果不构成稳定性、性能或整个设备测试集的通过证明。

## 复现入口与证据口径

常规环境可从仓库根目录使用以下入口；设备需满足[运行条件](设备测试.md#运行条件与设备影响)。

```powershell
.\gradlew.bat :app:clean :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest --no-build-cache --console=plain

$deviceTestClasses = @(
    'github.vhoom.zhijian.accessibility.ForegroundEvaluationTest'
    'github.vhoom.zhijian.fixture.FixtureCleanupTest'
    'github.vhoom.zhijian.runtime.interception.InterceptionPriorityRuntimeTest'
    'github.vhoom.zhijian.runtime.interception.GroupedContinuousUsageTest'
    'github.vhoom.zhijian.runtime.interception.RepairContinuationTest'
    'github.vhoom.zhijian.runtime.interception.GroupedInterceptionServiceTest'
) -join ','
.\gradlew.bat :app:connectedDebugAndroidTest "-Pandroid.testInstrumentationRunnerArguments.class=$deviceTestClasses" --console=plain
```

本机后续 Gradle 设备启动器因受限目录无法写入而在用例开始前失败。最终使用工作区临时 Gradle 缓存完成离线编译，再安装对应 APK，通过 ADB 直接调用同一测试运行器完成后两类验证：

```powershell
$metadata = Get-Content -Raw -Encoding UTF8 app/build/outputs/apk/debug/output-metadata.json | ConvertFrom-Json
$debugApk = Join-Path 'app/build/outputs/apk/debug' $metadata.elements[0].outputFile
adb -d install -r $debugApk
adb -d install -r -t app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -d shell am instrument -w -r -e class github.vhoom.zhijian.runtime.interception.RepairContinuationTest,github.vhoom.zhijian.runtime.interception.GroupedInterceptionServiceTest github.vhoom.zhijian.test/androidx.test.runner.AndroidJUnitRunner
```

本地数量依据 `app/build/test-results/testDebugUnitTest/TEST-*.xml`，不计清理前残留的旧编译类。Gradle 设备批次以 XML 的 `testcase`、失败和跳过节点为准；ADB 批次以每个方法的 `INSTRUMENTATION_STATUS_CODE` 及最终 `OK` 汇总为准。安装成功、ADB 进程退出码和编译成功均不能单独作为测试通过的依据。
