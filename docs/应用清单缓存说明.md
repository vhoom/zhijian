# 应用清单缓存

管控中心首次在后台读取系统中的可管控应用，保存成功后展示清单；此后默认读取设备本地快照。点击“共 X 个可管控应用”前的刷新图标才重新扫描并提交清单。界面行为见[界面与配置说明](界面与配置说明.md#管控中心应用清单)。

## 组件与数据范围

`data/source/CachedAppCatalog` 代理系统读取，接收实际扫描策略和 `data/store/apps/AppCatalogCache` 持久化接口。`AppCatalogFileStore` 实现文件读写；`MainActivity` 在原有后台 `TaskQueue` 调用代理，成功后一次更新列表与数量。

清单保存应用包名、显示名称及系统读取器生成的名称顺序，沿用现有可管控应用筛选。应用图标继续通过 `InstalledAppSource.iconOf()` 按需读取，并复用原有内存图标缓存。规则来源、搜索结果和使用统计由各自模块读取当前数据。

## 文件与提交

文件为 `getNoBackupFilesDir()/launchable_apps.cache`，位于设备私有、不参与备份的目录。当前格式使用 `DataInputStream` / `DataOutputStream`：依次保存四字节标记 `0x41505053`、整数格式值 `1`、整数应用数量，再逐条写入包名和名称的 `writeUTF` 字符串。

读取校验标记、格式、数量范围、非空且不重复的包名、完整记录及文件结尾。数量范围为 0 到 100000；每个字符串遵循 Java 修改版 UTF 编码的长度限制。清单中的 `AppInfo` 不可变，代理返回独立不可变列表。

写入先在同目录创建临时文件，完整写入后刷新缓冲并同步文件，再原子替换正式文件。替换成功才返回新清单；扫描、编码、同步或替换失败保留上一份已提交文件与页面展示。临时文件不参与清单读取，提交结束时清理。此缓存独立于 Room 数据库。

## 加载状态

| 情况 | 默认读取 | 点击刷新 |
| --- | --- | --- |
| 尚未保存 | 扫描系统，保存后返回 | 扫描系统，保存后返回 |
| 有有效清单，包括空清单 | 读取本地清单 | 扫描系统并替换清单 |
| 文件损坏或无法读取 | 报告失败，保留已有展示 | 重新扫描并尝试保存，成功后修复 |
| 系统读取或提交失败 | 报告失败 | 报告失败，保留已提交文件与已有展示 |

多个代理实例通过共享锁串行读取与提交，首次加载在获得锁后重新检查快照，避免页面重建期间重复扫描。刷新按钮和宿主加载状态阻止同一页面重复提交读取任务。应用安装、卸载、名称及名称排序变化在主动刷新后进入新快照。

首页手动条数的最大值使用最近成功保存清单的应用数。设置表单打开和保存前通过独立后台队列直接读取 AppCatalogFileStore，不走缺失时会扫描的 CachedAppCatalog.load(false)。缺失、空或损坏快照在输入下方说明，保持原设置；读取完成后检查弹窗身份、请求代次和页面生命周期，过期结果不更新表单。
