# 页面与配置引导

字体、字号、间距、圆角、深浅色、弹窗和提示的共用配置见 [UI 设计规范](UI设计规范.md)。本文说明当前页面行为。测试分类、夹具与运行条件见[测试目录与运行说明](testing/README.md)。

首页和管控中心共用顶栏。两个标题保持固定的左右顺序，当前页使用较大字号与深色文字，另一页缩小、淡化并稍微下沉，以位置表示方向。横向拖动时两页跟随手指平移并轻微淡入，松手后用 180 ms 动画完成切换或回到原位；系统关闭动画时立即归位。标题点击共用同一套归位逻辑，页面重建时恢复当前页和引导展开状态。

首次建立全局配置时，执行强度默认为“随心”。已有配置继续读取用户保存的强度，重新启动和覆盖安装不会将“修心”或“静心”重置为默认值。

## 首页用时日期选择

时长卡片在榜单下方使用两行七列日期组件，上行固定显示“一、二、三、四、五、六、日”，下行显示该周日号。默认选择今天，以“今”代替日号；今天保持实际星期列，其右侧的未来日期使用禁用颜色且不能点击。选中日期使用主题已有的绿色高亮，浅色和深色共用状态资源。日期条缓存当前及相邻日期段，只移动下行日期；拖动时跟手显示相邻日期，释放后根据位移和速度以 160 毫秒轻微吸附到星期对应位置。短距离低速拖动归位，未来边缘有阻尼且不允许进入未来整周，取消和打断动画不改变所选日期。长按可选日期可跳转远期历史，读屏提供前后周操作与完整日期描述。

榜单默认条数由 `UsageRowBudget` 按首页实际可用高度、强度卡片、时长标题、日期组件和应用行高度计算；预算不包含配置引导，使隐藏引导时日期选择靠近可视区底部。`UsageListScrollView` 用同一预算限制可见列表的完整行数：条数达到屏幕容量后不再向下增加卡片高度，超出行在列表内部滚动，总时长和日期位于滚动区域外。达到容量时，不足一行的空间用日期上方的留白补齐；至少保留一行，极小窗口仍允许首页纵向滚动。设置页和输入框直接显示计算后的数字，不增加“自动”文字或模式选项；手动输入覆盖计算值，恢复默认重新使用实测数字。屏幕和字体变化重新计算显示上限，计算结果不会覆盖手动输入。

榜单按实际生效数字创建完整行位。未满一分钟的应用不显示，应用不足时用不可见行保留高度；空日、加载和缺少记录也保持行位。行名限定单行并省略溢出，空行使用相同文本样式参与测量，支持大字体。日期筛选只更新下方时长榜单和屏幕总时长，并将内部列表回到顶部；上方执行强度、额度进度仍读取今日系统统计。列表有可滚动内容时接管纵向手势，到达边界后允许外页滚动和下拉刷新；横向手势交给首页翻页容器。

日期查询从本地永久归档读取，保存方式见 `本地存储设计.md` 的“每日使用归档”。快速切换通过查询代次和选择日期校验防止旧回调覆盖新榜单；页面重建保存实际选择日期，跨日时今日选择自动前进，历史选择保持原日期。`ui/binder/DashboardBinderTest` 的回归用例覆盖行位高度、执行强度分离、容量边界、超量内部滚动和切换日期归顶；本次合并未运行测试、编译或手机验证。

## 下拉刷新

首页下拉刷新提示初始化在容器外且不可见，只在真实下拉或刷新过程中显示。回收完成、取消手势、动画关闭和页面销毁均恢复隐藏状态；水平手势不会被识别为下拉刷新。`ui/component/navigation/PullRefreshLayoutTest` 保留透明首页提示隐藏与取消下拉的回归用例，日期跟手用例归入 `ui/component/usage/UsageDateSelectorTest`；本次测试整理未运行测试或编译。

## 管控中心应用清单

首次加载在后台读取系统中的可管控应用，将包名、名称及原有名称顺序保存为设备本地清单。此后启动、返回页面和首页下拉读取已保存清单；空清单也表示首次加载已完成。新增、卸载或改名后的应用在主动刷新后更新。

数量行开头显示 18dp 圆角线条刷新图标，其后间隔 4dp 显示“共 X 个可管控应用”。图标布局宽度收紧为 18dp，去掉水平内边距和额外左侧间距，由透明数量行的触摸代理保留至少 48×48dp 点击区。数量文字、间距、按压反馈和深浅色状态沿用 App 共用资源，图标默认无边框和底色；管控页面顶部增加 8dp 留白，数量行至少 48dp 宽高。点击图标才重新读取系统并保存清单，当前搜索词继续生效。读取和保存期间按钮不可重复点击，使用共用禁用颜色，读屏说明同步为读取状态；箭头仅在管控页处于前台时旋转，完成后恢复，系统关闭动画时保持静态图标。

只有保存成功后才替换列表与数量；读取或保存失败保留已有展示，并用原生 Toast 提示重试。损坏的缓存通过读取错误报告，主动刷新可以重新读取并修复。清单格式、提交边界及图标读取方式见[应用清单缓存说明](应用清单缓存说明.md)。

## 规则状态与应用顺序

规则组列表保持组名原文，勾选框右侧独立显示“已开启／已关闭”。只有保存成功后才更新显示状态。

管控中心按同一份 `PolicySnapshot` 解析标签和排序：有选中规则的单独配置显示“单独生效”，规则组配置显示实际组名。一个应用属于多个组时，取规则组列表中最靠前、已开启且选有规则的组；跳过关闭和空组。标签过长时单行省略，无障碍描述保留完整组名。应用依次按“单独生效、规则组生效、无生效规则”排列，每类内部保持原来的名称顺序；搜索保留此顺序。从编辑页面返回时立即刷新来源，再异步读取本地应用清单。这里显示配置来源，不代表某条限时规则此刻正在触发拦截。`AppListOrderTest` 的回归用例覆盖来源优先级、同类稳定顺序和搜索；本次未运行测试或编译。

新建草稿自动使用未占用的“规则组 1”“规则组 2”等名称，已关闭组也占用名称。保存默认名称前重新检查，用户自定义的名称和已有组名不自动改写。

## 规则编辑

规则用量与首页历史展示分开：本次安装内每个策略首次启用后，从成功保存的生效边界开始统计，不追算启用前的系统使用记录。正常运行中切换随心、修心或静心保留原起点和累计量，服务重连、进程重启及覆盖安装也不会重新起算。每日、时段和滚动额度仍按各自自然边界恢复；时段禁用按日程立即生效。持久化与回归范围见[规则计时起点](architecture/规则计时起点.md)。

单应用页首次启用或编辑规则时自动开启独立配置总开关，复制上一份配置也会开启；首次查看、参数回填、页面重建及重置不会误开启。底部“重置并关闭”经原有确认后恢复跟随规则组或全局策略。单应用和规则组编辑页统一使用“提醒规则”标题及一个规则容器，依次展示全天限时、全天限次、全天频率限次、全天连续使用提醒、时段限时、时段限次、时段连续使用提醒、时段禁用，不再分为禁用与提醒两个配置区。“破例放行”在八条规则下方，标题与分钟输入同行，补充说明放在下一行。规则组列表仅显示“组名 · 应用数量”和启用状态，不显示规则摘要。

规则组配置页在“提醒规则”下显示12sp小字“同组内所有配置共享额度”。同组应用共用全天限时、全天限次、全天频率限次、各时段限时与限次，以及全天和时段连续提醒的对应累计量，时段禁用统一作用于组内应用；组内切换不会重置用量，休息状态和破例放行也按组共享。各条规则保留自己的阈值、统计周期及独立时段。统计范围按 `PolicySnapshot` 的实际生效来源确定，独立配置或由更靠前规则组接管的应用不消耗本组额度。共享说明使用共用文字和深浅色资源，仅在规则组配置页显示。

默认组编辑页直接列出本机已安装成员，支持逐项移除，明确保存后生效；成员较多时在最高240dp的子块内滚动，不提供“查看应用”按钮。首次全选或七天都有已保存规则时标题为“每天”，只配置部分星期时为“指定星期”。名称、星期规则、规则条件、放行时长和删除操作继续保留。普通自建组编辑页依次展示名称、管控应用、规则条件和放行时长。应用选择支持搜索与多选，至少选择两个不同应用才可点击完成并更新草稿；不足两个时完成按钮不可用，保存也会在应用区域提示。页面最多预览三个应用。八种规则各用一张卡片，启用后参数直接展开在卡片内。

`RuleConditionsEditor` 由规则组和单应用页面共用，集中定义配置页展示顺序，不改变规则类型枚举顺序、计时判定优先级及拦截模式设置。全天连续提醒及每个时段连续提醒将“使用”和“休息”分钟参数放在同一横行，两个输入框分别保存数值，参数标签、单位、时间与时长数字统一12sp，紧凑矩形框保留最小尺寸，内容超出时扩展。组合参数使用浅灰面板：上行是包含开始、结束和删除操作的一条白色时间行，下行并排显示使用、休息参数，单项参数容器保持透明；添加时段按钮也在同一面板内。可用宽度不足时两行一起横向滚动，不压缩字号或截断标签。四种时段规则分别支持添加、删除多个时段，限时时段每段独立设置时长额度，限次时段每段独立设置整数次数，时段提醒分别设置使用与休息时长；跨午夜的编辑框分两行显示“次日”和时间。保存前校验启用类型是否有时段、起止是否相同、每段额度是否填写，错误定位到具体时段。取消勾选保留参数，重新启用时恢复。`RuleDraftState` 统一保存未提交草稿与稳定时段 id，避免页面重建时重复控件 id 覆盖其他行的输入。

规则组和单应用编辑页通过 `values/rule_editor.xml` 引用全局样式与语义色，深色从共用 `values-night/colors.xml` 读取。页面边距、卡片内边距和主卡片间距均为16dp，主卡片圆角12dp。规则名称16sp、说明14sp，参数标签、单位和行内数字统一12sp（包括全天限时、限次及破例放行的输入值和单位），开关使用全局52dp轨道。连续提醒和时段参数按“短标签、数值、单位”紧凑排列：时间标签与框间距6dp，使用休息标签和单位与框间距4dp。时间框最小62×30dp，使用休息数字框最小46×28dp，均采用浅灰表面、1dp描边、6dp圆角和四周4dp内边距；数字框按最小宽度与当前最长行宽加复合内边距的较大值显示，内容或系统字体增大时扩展。透明外层至少48×48dp，以触摸代理保留完整点击范围。多项组合的浅灰面板圆角12dp、内边距10dp，白色时间行圆角8dp、水平内边距10dp，单个参数行不套背景或额外内边距，行间和双参数间距8dp。“添加时段”为12sp文字的整行虚线按钮。按钮和输入框保留至少48dp触控高度。星期视觉块外留4dp触控边距，七项等分可用宽度；宽度不足时横向滚动。

破例放行时长输入框与使用、休息输入框使用同款浅灰矩形样式：最小46×28dp、6dp圆角、12sp数字，与分钟单位间距4dp。两个编辑入口都绑定共用尺寸观察器，内容超出时扩宽，透明容器保留至少48×48dp触控范围。

全天限时、全天限次也使用同款数字框，单项参数行直接显示在主卡片内，不叠加浅灰面板或白色子卡。规则组名称采用同样的浅灰表面、细描边、6dp圆角和12sp字体，保留整行宽度。两个页面通过 `RuleInputFocus` 统一输入交互：点击输入区域外或键盘完成后失焦并收起键盘；切换到另一个输入框时保留键盘。名称及规则数值在失焦前已进入原有草稿，失焦不会提交配置或清空输入，按钮、开关、滚动及原生校验继续正常处理。

时段限时的每个时段以一行显示开始时间、结束时间、使用额度和删除按钮；额度复用原有输入框及草稿绑定，不增加单项背景。窄屏或大字体时整行横向滚动，多个时段仍逐行排列，添加时段按钮位于列表下方。

全天限次、时段限次与全天频率限次都允许前 N 次真实打开，第 N+1 次触发对应强度的限制。次数输入框不显示“1–99”，编辑时不提示范围错误；保存时统一检查整数范围，失败保留原输入，继续编辑时清除旧错误。未填写的数值草稿使用零值，原始文本单独保留，程序回填不触发用户编辑。同应用内部页面交接与实际拦截页返回不重复计数，离开到桌面、锁屏或其他应用后返回计为真实打开；组内各成员的真实打开消耗同一条额度。

全天限次按设置的每日恢复时间重置；时段限次在各独立时段结束时恢复，跨午夜采用开始星期的配置。全天频率限次始终只有一个滚动窗口和次数组合，记录在到期毫秒移出统计范围，午夜不清空近期打开。多条禁用同时生效时，禁用决定使用最晚自然解除时间，下一次复查采用较早的额度释放边界。引擎、运行层及拦截页传递同一复查要求，页面步骤变化和异步查询耗时不延后期限。统计、存储及扩展入口见[限次规则设计](architecture/限次规则设计.md)。

### 手动输入校验

名称、数值格式和上界统一在保存或“确认应用”时验证，输入中不显示范围错误。所有时长仍以分钟输入，最多一位小数；输入框保留粘贴原文，不能把多余的小数位、符号或超长数字过滤成另一个合法值。

| 输入项 | 保存约束 |
| --- | --- |
| 规则组名称 | 去除首尾空格，最多20个Unicode字符；留空沿用自动命名 |
| 全天限时 | 0至720分钟；启用时必须明确填写，零值可保存 |
| 全天、时段、频率限次 | 1至99的整数 |
| 频率统计窗口 | 大于0且不超过60分钟 |
| 全天连续提醒：使用、休息 | 均大于0且不超过720分钟 |
| 时段限时额度 | 大于0，不超过720分钟及当前时段长度 |
| 时段连续提醒：使用 | 大于0，不超过720分钟，且必须小于当前时段长度 |
| 时段连续提醒：休息 | 大于0且不超过720分钟 |
| 破例放行时长 | 大于0且小于720分钟 |

关闭的规则允许保留空值或零值，已填写的原文仍检查格式及绝对上界；时段长度约束在对应规则启用时生效。名称上界仅作用于手动组名，单应用内部用于身份的包名不套用该限制。空名称的自动命名在校验通过后生成，只有保存成功才回填输入框。

无效格式、缺失必填值或下界错误提示“无效，请修改”，超过数值上界提示“数值过大”。两个入口通过 InputError 将文字显示在所属控件下方，框内不插入错误图标或气泡，不弹独立校验对话框；提示复用14sp文字和共用深浅色错误资源，按触控容器宽度换行。保存失败立即定位原输入并滚动、恢复键盘；收起参数使用所属卡片提示和开关入口，不自动启用规则。其他星期的错误保留当前草稿，使用卡片或星期入口回退定位，不标记当前日的无关输入。

校验和存储失败保留全部原文，包括启用后的空输入、两位小数和超大整数。`RuleInputBinding` 按类型、时段稳定ID及参数角色保存文本，页面重建在星期草稿绑定后恢复，避免重复控件ID或数值零值覆盖原文。时段增删仅重建对应列表，保留仍存在时段的输入；打开时间选择器不释放数值绑定。`RuleInputLimits` 共用不可变约束，`RuleGroupValidator` 负责模型上界和完整候选检查，事务成功后才更新星期保存标记及复制来源。

当前回归声明涵盖精确上界、严格放行上界、明确零值、休息与次数错误角色、粘贴原文、时段重绘、系统恢复和输入反馈生命周期。本次仅静态核对源码、资源及差异，未运行测试、编译、Lint 或设备视觉验证。

## 共享引导

`view_setup_guide.xml` 在首页展示五项独立入口；第一行展示无障碍与使用情况访问，第二行并排展示电源设置与自启动，第三行由后台运行使用完整行宽。`view_setup_settings.xml` 在设置页按无障碍、使用情况访问、电源设置、后台运行、自启动排列为五项紧凑列表。引导图标来自项目内 `res/drawable/ic_setup_*.xml` 矢量资源，共用尺寸、线条和主题文字色。首页用量榜的应用图标通过 `InstalledAppSource.iconOf()` 调用系统 `PackageManager.getApplicationIcon()` 获取，无法读取时显示本地占位图。两种布局使用同一个 `SetupGuideBinder`；`SetupGuideState` 适配 `PermissionStatusReader` 的真实快照，`SetupGuideDialogFactory` 共用说明和条件文案，系统跳转与缺失入口回退由 `PermissionIntents` 处理。

| 入口 | 状态来源与行为 |
| --- | --- |
| 无障碍 | 查询指定服务的授权和真实连接，区分未识别、未开启、已授权但未连接、已连接；提供应用信息与无障碍设置入口，Android 13 及以上未授权时追加受限设置步骤 |
| 使用情况访问 | 查询 AppOps 授权，说明用途、开启步骤和受限设置提示；优先定位本应用，失败后打开使用情况访问列表 |
| 电源设置 | 显示真实忽略电池优化状态，点击直接打开说明；未开启时申请，已开启时查看系统列表 |
| 后台运行 | 作为独立配置行显示手动检查或系统警示，点击直接打开说明；保留弹出界面权限和近期任务锁定步骤，并追加适用的后台受限及页面未确认显示警示 |
| 自启动 | 显示厂商设置检查步骤，可打开通用应用信息页；状态保持“手动检查” |

返回页面时重新查询系统状态，不以本地偏好证明权限已经开启。厂商的自启动、后台弹出界面与近期任务锁定没有统一查询接口；自启动和后台入口在没有可检测警示时保持“手动检查”，不会因点击入口就变成已完成。五项入口均直接打开各自说明，电源和后台各自保留取消、前往设置两个按钮，无障碍说明另有打开应用信息按钮。

后台引导不按手机品牌分类。`PermissionIntents` 直接打开通用应用信息页；入口缺失或访问被拒绝时回退系统设置首页。各手机只检查系统实际提供的选项，无法统一读取的自启动和后台弹出界面保持“手动检查”。所有页面和授权操作均由用户主动打开、确认。

## 无障碍授权与连接

`ZhijianAccessibilityService` 已在 Manifest 注册，系统通过 `BIND_ACCESSIBILITY_SERVICE` 保护绑定。配置只订阅窗口切换事件，不请求窗口内容读取能力。服务负责授权与连接生命周期，接收前台窗口切换并调用独立运行模块解释规则；规则命中后启动全屏拦截。页面实际获得窗口焦点后提交回执，超时未确认时保留日志并提示检查后台显示。运行规则与恢复行为见 `architecture/拦截架构设计.md`。

`AccessibilityConnection` 只保存本进程的真实连接。服务连接、解绑、销毁时更新状态，旧服务实例销毁不会清除新实例的连接；进程重启后不会沿用上次的“已连接”。授权由 `PermissionStatusReader` 按精确组件名查询，避免把同包的其他服务误认成当前服务。

`PermissionStatusObserver` 仅在页面可见时监听系统授权项与连接回调；离开页面注销并清除待执行刷新，返回时重新读取，避免开启后状态停留在旧值。无障碍详情页使用部分系统支持的兼容入口，携带 `Intent.EXTRA_COMPONENT_NAME`；失败时打开公开的无障碍列表。Android 13 及以上附有“受限设置”的手动处理提示和应用信息入口。已授权但未连接时提供关闭再开启服务的恢复步骤。

## 设置与关于

`GlobalSettings.showSetupGuide()` 默认开启，仅控制首页引导是否可见。隐藏后，设置页始终保留全部配置入口。“显示每日古诗”紧接“显示配置引导”，由独立的 `GlobalSettings.showDailyPoem()` 控制，默认开启。关闭后移除首页诗句视图，返回首页立即同步，定时刷新和页面重建遵循保存值；不改变执行强度、额度或其他设置。诗句从本地 `values/poems.xml` 读取，`DailyPoem.of()` 按手机本地日期每日随机一次。当天正文保存在独立 `daily_poem` 偏好缓存中，返回首页、刷新、页面重建和重启均复用；日期变化后的首次读取重新选择，有其他正文时避开上次诗句，只有一种有效正文时沿用该句。缓存中的 `date` 与 `text` 同时更新并通过 `apply()` 异步落盘，保存正文而非数组序号；Debug 预览通过 `DailyPoem.random()` 独立抽样，不读写每日缓存。主题与用量榜显示条数沿用原有偏好。

设置页按外观与首页、随心、修心、静心、权限与运行、关于组织。连续使用提醒不再单列交互设置，按当前强度复用拦截页面；使用阈值与休息时长仍在规则编辑页配置。主题、用量榜条数以单行展示当前值，点击打开选择或输入弹窗，条数支持恢复默认。手动条数必须为1至最近成功扫描并保存的可管控应用数；打开表单和保存前均在后台只读扫描快照，不自动发起扫描。读取期间禁止保存；缺失、空或无法读取时在输入下方说明并保留原设置。上限按完整清单计算，不随搜索或当日记录缩小；超过屏幕容量的合法条数继续在列表内滚动。所有参数的合法范围、相对限制和含义见[合法值参考表](合法值参考表.md)。“关于”将作者的话、服务协议、诊断日志与底部应用图标、应用名和版本信息放在同一区域。应用名称读取 `brand.xml` 中的 `app_name`，版本读取构建信息；Debug 连点图标七次的预览入口保持独立。作者信和协议从 `assets/about/` 的独立文本文件读取，正文中的 `{{app_name}}` 自动引用当前名称，共用阅读页面，作者信采用书信字体和换行。GitHub 图标按钮位于版本号左侧，同一行居中排列，不显示链接文字；点击后通过系统 `ACTION_VIEW` 交给可处理链接的应用或浏览器。地址集中在 `brand.xml` 的 `settings_github_url`，指向项目仓库 `https://github.com/vhoom/zhijian`。

首页引导收起后保留一行“配置引导”、功能状态和展开入口，点击整行可展开。功能状态依次检查使用情况访问和无障碍授权、服务连接、后台运行受限、拦截页面未确认显示；基础权限与连接满足且没有后台警示时显示“基础服务已连接”。电源和后台状态分别显示在各自入口内。

首页引导标题与每个网格入口将自身留白纳入点击区域，水波纹覆盖同一范围并按外层卡片圆角裁切。五个配置入口共用昼夜适配的 `control_highlight` 按压色和圆角遮罩；设置卡片裁切列表反馈，管控模式按钮以前景保留反馈，避免选中背景切换后丢失按压状态。用量权限提醒整行也提供圆角按压反馈。

引导和设置分组共用 `RoundedLinearLayout`，通过平台方法裁切按压反馈。普通确认、选择、日期与时间弹窗通过 `AppDialogs` 使用共用主题；挑战配置弹窗由 `SettingsBottomSheet` 负责。档位确认的长说明使用原生滚动正文。

应用图标采用提供的“止间＋时钟弧线”标志，保留原有造型，清理底色并增强细线。暖白背景 `#FCFBF8` 在 `brand.xml` 中维护，深蓝 `#222A54` 直接写入图标像素，避免安装器忽略位图着色后显示成白色。透明笔画位于 `drawable-nodpi/ic_launcher_artwork.png`，自适应前景按108dp画布内的60dp安全圆排布，避免圆形裁切丢失文字或星芒；普通和圆形图标包含五档密度，系统单色主题复用透明笔画。“关于”页使用裁掉透明安全留白的 `ic_settings_logo_artwork.png`，通过 `bg_settings_logo` 复用暖白矩形底色；方形背景为56dp，图案宽约48dp，点击区域保留64dp。

设置中的“诊断日志”提供刷新、导出 ZIP 和清空入口。文件保存位置由 Android 文件选择器决定，导出状态显示在诊断页；清空前通过共用弹窗确认。当前设置页没有独立的历史用量 JSONL 导出行。诊断范围与保留策略见[本地诊断说明](本地诊断说明.md)，用量存储与导出接口见[本地存储](本地存储设计.md)。

## 拦截文案

动态文案共十类：普通拦截主句、按压挑战主句、单词风暴主句、数独完成语句、再次确认主句、单词选错文案，以及退出、继续使用、前往挑战和盲盒控件文案。普通主句供提醒、限制及随心、修心、静心共用；临时放行与继续使用共用控件文案，实际行为仍由原设置和状态机决定。

英译中和中译英各保留一个固定题干模板，填入当前单词或中文含义；按压提示、完成文字、题号、秒数及进度同样使用固定措辞。文案库按用途分为 XML 文件，四类主句使用各自的不放回洗牌队列，抽完一轮才重洗，换轮时避开上一轮末句。同一规则当前这轮拦截的主句保持不变，重新打开、后台返回、重复请求及页面重建均读取已选正文；新会话首次显示对应页面才抽取新句。正文及分类轮换进度保存在独立偏好文件中，Debug 样例不推进正式队列。维护位置见[拦截文案库说明](拦截文案库说明.md)。相关回归源码已同步，本次仅完成静态检查，未运行测试或编译。

## 模式拦截开关

随心区提供“临时放行”（默认关闭）和“动态按钮”（默认开启）；修心区提供“临时放行”“阻碍页面”和“再次确认”，默认均开启。随心与修心的放行设置分别保存，切换一个不会改变另一个。

动态按钮的小字说明为“变化多端的样式”。开启保留随机按钮／滑块组合、随机上下位置及双退出、盲盒事件；关闭时两个普通按钮固定为继续在上、退出在下。该开关仅影响随心首屏，修心及最终反问保持独立；系统重建使用原会话保存的开关，不随设置修改重抽样式。

正式随心、修心每次重新打开首屏时使用新的独立控件种子，包括同一 Activity 从后台返回；随心可重新选择普通控件、双退出或盲盒，修心继续使用一退一进的普通控件，抽样允许偶然出现相同组合。主句保留原会话内容并始终显示，旋转和进程重建复用本次打开的控件种子。后台规则复查保留当前组合，首屏重新抽样独立于挑战阶段与原休息期限；显式 Debug 预览继续按稳定会话重现指定样例。

修心开启阻碍页面时显示再次确认、按压挑战、单词风暴和数独挑战配置，继续时从已开启的挑战中选择一种。默认开启阻碍页面，仅开启按压挑战，按压时长在 50～75 秒内随机；单词和数独默认关闭。单词参数保留 17 题、每题至少停留 2 秒、初中词库，数独默认难度为简单。默认值仅用于没有保存相应设置时，用户已保存的开关、时长和难度继续优先使用。三种挑战各有独立开关；只剩一个开启时锁定该开关，仍显示正常开启的轨道和滑块颜色，并说明“阻碍页面至少保留一种挑战”。开启另一项后解除锁定，按压与单词参数入口保持可用。再次确认的小字说明为“挑战后的再次确认一下你”：开启时挑战完成后进入反问页，再选择退出或继续。

数独每次完成 9×9 一局，设置摘要只显示当前难度“简单／中级／困难”，点击后可在底部弹窗选择；取消不保存，确认后从下一局生效。页面左右留白为 12dp，棋盘数字使用 20sp；九个数字按钮使用 18sp，按 3×3 排列在基础宽度 168dp 的键区内，默认字体下按钮为 48dp 方形，居中略向右偏，不设独立清除键。选中可填写格后点击数字填入，再点与格内相同的数字清空，点击其他数字替换，无需快速双击，清空同样保存进度。棋盘与键区按屏幕可用宽高一起缩放，完整展示且无滚动。题目预填数字不能选中或修改，点击也不改变当前可填写格的选择；行、列和宫重复时标记冲突。

单词和数独在尚未开始时退出再进重新出题：单词未有效选择答案、数独未成功填写均属于未开始。单词答错也算开始，数独填写后再清空仍算开始。开始后的未完成局全局保留，退出、切换目标应用或重建后继续原局；修改配置不会清空已答进度。旋转、切换主题等原次进入内的重建不刷新题目。两类挑战都在后台原子保存成功后更新答题进度。数独答题时没有主句；完成后九键退场、终盘上移，在按钮上方显示按本局身份选定的动态完成语句，动画结束后开放继续操作；有反问时点击继续才进入反问页，没有反问时沿用原继续流程。页面重建保留终盘，结束本次拦截后的下一次挑战才换题。保存失败显示系统提示与重试入口；Debug 预览使用独立内存进度。详细边界见[挑战进度与重新进入](architecture/挑战进度与重新进入.md)和[数独挑战与进度](architecture/数独挑战与进度.md)。

关闭再次确认时，挑战完成直接更新当前页面，主句和原退出按钮保持不变。按压按钮显示“按压已完成”，按压进度保留满格；单词题目显示“单词挑战已完成”，最后一题的六个选项及满格进度仍然显示。完成后的挑战控件停止接受输入，底部在退出按钮后新增继续或临时放行操作，并以 200 毫秒的淡入上浮动画出现。必须再主动点击新增按钮才执行继续，完成手势及按钮浮出期间不执行放行；系统关闭动画或恢复页面时直接显示完整按钮。

关闭阻碍页面时三块子项一起隐藏，并跳过挑战与后续选择；重新开启恢复原再次确认值、区间、词库、题量、停留时间，以及按压和单词各自的开关。挑战选择由同一策略约束保存与读取：有效的单一挑战按原样保留，关闭最后一个挑战的请求不生效；仅在读取到异常空集合时回退按压。开关保存在已有 SharedPreferences 键中，不改变数据库结构，进行中的拦截会话继续使用其冻结配置。

子项内嵌在阻碍页面开关下方，以缩进、独立底色和圆角描边区分父子边界。用户切换时用 220 毫秒的布局过渡与淡入淡出同步展开或收起，下方设置随布局平滑移动；首次打开、页面重建及系统禁用动画时直接显示保存状态。收起期间子项退出读屏导航，已有参数保持不变。

独立挑战开关的回归已同步到 `ChallengeSelectionPolicyTest`、`GlobalSettingsTest` 和 `InteractionModesTest`，覆盖双开、单开保护、仅单词持久化、阻碍总开关及页面重建；本次仅静态核对，未编译或运行测试。

流程策略把关闭反问的按压／单词完成态保存为独立阶段。当前挑战页通过统一的原页完成接口更新已有控件；系统重建时由页面目录恢复对应挑战布局，直接显示完成文字、满格进度和双出口。单词完成态按冻结的会话种子重现最后一题的选项并锁定，不重新挑战，也不插入后来开启的反问页。完成事件仅推进状态，导航与通行证仍由统一状态机在用户继续时执行。提醒的原休息期限保持独立。

临时放行的小字说明为“是否启用规则中的特殊放行”。关闭后，随心和修心的全天、时段连续提醒仅在明确继续使用时保存新增用量起点，同组应用共享下一轮提醒间隔；选择退出只记录退出结果，保留原提醒和未完成休息，休息不足时进入同组其他应用仍会拦截。足额连续离组休息后按原流程恢复。随心禁用页点击继续，或修心完成本会话配置的挑战和反问后点击继续时，忽略当前应用本次访问中的全部禁用规则，包括后续才达到的限时、限次或禁用时段。修心关闭阻碍页面时直接继续也保存同样的确认，连续提醒仍照常检查。拦截页返回与同应用页面切换不算下次使用；离开应用后重新进入或锁屏后重新使用时恢复检查。同组其他应用不共享禁用忽略，更新规则后重新检查。开启后最终继续按原规则的时长临时放行。设置只影响之后的新会话，页面重建保留本次选项；后来开启临时放行不会撤销已经保存的本次访问确认或提醒的新增用量起点。

仅修改组名、原样保存或把每天参数等价展开为七日配置时，保存名称及当前格式，保留规则版本和已完成挑战；参数、成员或启用状态实际改变时推进版本并重新判定。

修改连续提醒的使用阈值并保存后，提醒选择、展示决定与弹页前复查统一读取当前已生效配置：全天提醒使用当前日期参数，时段提醒使用相同窗口身份的最新参数。已确认提醒从原确认用量起点计算新增实际用量，阈值调低后达到新边界即再次提醒，调高后按新间隔等待；原累计用量、触发身份和发生时间保留。未完成休息时调大立即提高本轮要求，调小保留本轮较大要求，完成后下一轮采用小值。当前日期没有对应规则或窗口时，仍保留的原休息沿用原阈值。

`PendingInterceptionStoreTest` 分别覆盖提醒退出与明确继续的正式结果写入、存储重建及同组下一目标的提醒判定，组合随心、修心与全天、时段连续提醒，并核对原用量和休息要求保留、足额休息解除。`ReminderRepeatPolicyTest` 覆盖新阈值升降与边界，`ReminderThresholdRuntimeTest` 通过提交新配置、准备原提醒和独立周期，再调用正式运行入口，覆盖同应用、同组换应用及最终展示检查。本次仅完成静态核对，未编译或执行用例，手机端修改后效果尚未验证。

本次访问忽略由独立私有偏好 `block_continuations` 保存应用、策略版本、确认时档位、触发类型、窗口、启动身份和本次点击继续的确认时间；进程重建可恢复，设备重启不延续。随心和修心的确认分别匹配对应档位，另一档不能继承，静心不接受确认。当前存储格式要求完整档位字段，缺失或损坏的记录不生效。复用旧拦截会话时，原触发时间仍用于审计，访问复查只查询本次确认之后的事件，不把确认之前的离开和重进算成下一次访问。同一次访问保存一份完整确认，后续确认原子替换原边界；旧复查不会清掉后来确认的新访问。

快速切换同组应用时，旧禁用结果由后台串行队列转交，并在周期锁内保存当前目标的完整展示身份；落盘后再次核对前台代次再启动页面。旧提醒仍完整复查当前目标的禁用边界。页面恢复同时核对会话身份，不仅比较原因，避免点击继续确认被遗漏。

结果异步保存后，在周期锁内核对当前展示会话、实际确认的规则及展示时间；保存期间换入其他触发类型、窗口、策略版本、档位或新展示时，旧回调不放行新规则，也不清除新页面。日志分别记录确认已应用或因规则、会话和访问变化而跳过，审计保存成功不等于确认生效。系统用量证据在偏好锁外读取，清理只匹配被复查的原快照，避免删除并发写入的新确认。无障碍后台记录真实前台切换，同包窗口通知也安排尽快复查，但不伪造新访问或推迟原阈值检查；忽略不创建通行证，不清除真实用量或未完成休息。运行层保存展示前和服务实际启动页面前，都再次核对本次确认和有效临时放行，丢弃已经失效的旧计算结果。

## 静心再次进入

静心首次触发防沉迷时正常显示拦截页面。同一轮限制尚未解除时，第二次、第三次及后续每次真实进入目标应用，分别以相同概率选择“只模拟系统返回”或“先模拟系统返回，再显示拦截页面”。使用 `SecureRandom.nextBoolean()` 独立抽样，同包内部页面变化和本次访问的定时复查不增加进入次数，也不改变已选择的动作。

规则组默认共享这一轮状态：A 首次触发后进入同组 B，B 采用后续访问的随机动作。独立应用配置使用自身作用域，全局默认配置的返回动作按目标应用隔离。提醒以原触发事实区分轮次，禁用以规则及恢复边界区分轮次；更新配置、开始新一轮提醒或规则解除后重新从正常显示页面开始。动作状态由无障碍服务实例持有，服务实例重建后首次正常显示页面；原持久化限制与休息仍保留。

两种返回动作都等待 250 毫秒后检查真实前台，在需要弹页时后台复查规则，并检查最新强度、版本和目标归属。“只模拟系统返回”在目标已离开前台时不显示页面；如果返回仅关闭弹窗或退到应用内部上一页，目标仍在前台且限制有效，则显示拦截页兜底。目标仍在前台时，复查继续使用已确认的窗口时间补足延迟到达的系统用量事件。休息已经完成、规则解除或用户切到其他应用时，旧返回请求不再显示页面。快速再次进入不沿用上一访问的弹页去重；同次访问只执行一次被系统接受的返回，后续完整复查仍命中且目标仍在前台时，两种动作都继续尝试显示页面。系统拒绝返回操作时沿用正常拦截页面；具体返回导航由目标应用和系统决定。

返回后弹页请求已经发出时，同次返回的晚到桌面窗口事件继续保留实际窗口回执等待，页面未显示仍可产生超时诊断；切到其他应用或发生后续真实访问会取消旧等待，旧请求不再沿用。

随机动作不签发通行证，不清除真实使用量或未完成休息。回到目标应用仍会打断尚未完成的连续休息；停留在拦截页面继续计入休息。随心与修心采用原有拦截流程。

本次仅静态核对策略、返回后的前台兜底、窗口回执取消接线与修改差异；本地回归覆盖首轮、逐次随机、复查去重、组共享、独立配置和解除边界，设备用例覆盖多次进入后的真实前台与限制保留，以及只返回未退出时的弹页兜底、晚到桌面事件和其他访问的回执边界。未运行测试、编译、Lint 或设备验证，系统返回与后台弹页效果尚未实机验收。

## 连续使用与休息

随心、修心、静心共用连续使用和离组休息判定。统计范围由实际生效的单应用独立配置、规则组或全局策略决定；同一范围内切换应用继续累计，离开范围时暂停使用累计并开始连续休息。切到其他应用、桌面、止间页面或锁屏都按是否离开当前范围判断，静心不再单独限制休息场景。回到范围内会打断尚未完成的休息，多次短暂离开不能合并成足额连续休息。

连续非使用边界全局统一为五分钟，单应用、规则组和全局配置使用相同条件：连续非使用时间严格超过五分钟，或满足本轮有效休息要求，即结束连续周期。恰好五分钟且休息要求更长时保留累计；本轮休息要求为三分钟时，满足三分钟即可结束。配置提交前按旧参数结算真实使用和休息，提交后接管新参数；尚未完成时调大立即接管，调小保留本轮要求，完成后下一轮采用小值。配置保存本身不清零用量，多次短暂离开不能拼接。

时段周期包含窗口身份和实际起止时间，已触发提醒保存原统计终点。修改端点使窗口发生身份改变时，旧用量最多统计到原终点或配置生效时刻中较早者；原休息与确认用量仍保留，新窗口单独统计。例如09:00～10:00的提醒已明确继续，随后改为11:00～12:00，保存后在新时段外使用不再给旧提醒增加用量。

`ContinuousRestPolicy` 集中提供离组判断和实际休息时长；`ContinuousUsageReader`、`RuleEngine`、`ReminderRestPolicy` 及运行时页面恢复共用该判定，避免使用量已清零、提醒仍阻塞，或提醒提前完成而使用量尚未清零。全天连续提醒、时段连续提醒及结束窗口补查采用相同规则，周期身份、原窗口使用边界及真实休息代次继续分别保存。切换强度不重置累计进度，连续休息清零也不清除每日使用总量。

本次变更仅完成源码调用、边界用例和差异的静态核对；未运行本地测试、设备测试、编译或 Lint，尚未验证设备上的前台切换与倒计时表现。

## 星期独立配置

单应用及规则组编辑页在“提醒规则”前共用 `WeekdayRuleEditor`。标题为“为下面所有指定星期”，一行显示“一、二、三、四、五、六、日”；较窄屏幕可以横向滚动，点击目标保持 48dp 触摸范围。不提供每天入口、多选或独立星期开关。当前编辑星期使用浅绿底色与绿色边框，即使该日尚未保存规则也显示选中底色；已经保存规则的星期继续使用绿色文字与底色，边框独立表示当前编辑选择。浅色与深色复用各自的选中语义色。

首次进入空配置时七天全选，保存同一份初始规则到七天，成功后进入星期一单日编辑。已有配置进入第一个有规则的星期，之后点击数字只编辑该日。有未保存修改时需先确认应用或清除当前星期再切换，避免丢失输入。

带边框的操作左侧为“应用刚才的配置”，右侧为“确认应用”“清除应用”，按钮宽度适配文字，三项操作均不弹确认框。小屏或大字体时操作行可横向滚动，避免文字截断。复制使用上一次成功应用的完整参数，包括时段、次数、滚动窗口和放行时长，仍需确认应用；尚无来源时复制按钮显示但不可用。确认应用执行后台事务并留在页面，只有成功后才更新绿色标记和复制来源。清除应用直接清空当前星期并保存，保留其他星期和上一份应用参数；最后一个有规则的星期也可清除。首次空配置全选时清除不可用，避免误清七天；页面顶部保存继续使用原有保存并退出行为。

`WeekdayRuleDraft` 独立协调候选提交、成功确认和取消，页面重建保留当前星期、未保存输入、取消基线及上一份保存配置。切换使用 180 毫秒左右位移与透明度反馈，尊重系统关闭动画设置。数字按钮的读屏描述包含完整星期名称、配置状态和编辑状态。参数错误保留当前输入并定位对应控件。 新增的时段次数、频率窗口与频率次数进入同一套单日保存、复制、取消和页面重建快照；候选校验或写入失败时，原输入与其他已保存星期保持原值。

规则组的“全部重置”和单应用的“重置并关闭”二次确认后同时清空星期规则、未保存输入和上一份复制来源，并重新进入空配置全选状态。规则组保留身份、名称和应用成员，明确保存后提交；单应用恢复跟随策略。重新绑定星期协调器，防止继续编辑恢复重置前的数据。
